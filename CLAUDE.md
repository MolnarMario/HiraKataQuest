# CLAUDE.md — HiraKataQuest

**HiraKataQuest** — an Android app for practicing Japanese **kana** (hiragana + katakana, all groups). Since 2026-07-09 it splits into two top-level tracks behind an opening screen (`AppMode` READING/WRITING): **Writing** = trace a light-grey ghost glyph on a genkouyoushi-style grid with stylus or finger (free practice + a write-from-memory "Quiz me!" mode), attempts persist to Room; **Reading** = printed-glyph flashcards + an inverted reading quiz (recognize the glyph, answer by choice or typed romaji). Structured learning comes from **built-in default practice sets** (a guided SRS study session existed through 2026-07-04 but was removed 2026-07-05 — see the Status paragraph). Handwriting is auto-scored when the Score-my-writing setting is on. Kotlin, Jetpack Compose, Material 3, MVVM, Room via KSP, manual DI (no Hilt). Single module `:app`, single screen, package `com.hive.hiragana` (the package/`applicationId` is unchanged by the rename — the user-facing name lives in `strings.xml`).

**Status: Phase 1 (static tracing MVP), Phase 2 (animated stroke-order demonstrations), and Phase 3 (Smart Learning System — SRS scheduling, personalized sessions, vocabulary unlocking) are all COMPLETE**, plus a 2026-07-04 post-device-feedback batch: KanjiVG-sourced stroke geometry (viewBox 109, CC BY-SA attribution required — see `tools/import_kanjivg.py`), brush-ribbon ink rendering, a Start-next-session button on the COMPLETE summary, a Library overlay for free practice of any character/word, and a force-dark opt-out. Two 2026-07-04 content expansions then grew the deck from 5 to the full 46-character basic gojūon (あ〜ん via the same KanjiVG pipeline, frequencies = gojūon order 1–46; no dakuten/yōon yet) and `vocabulary.json` to 153 common words (every kana except を covered). A 2026-07-04 **katakana section** then added a second script alongside hiragana (device-verified on the Pixel 7): a `Script` enum + `assets/katakana/` (46 homologues + the long-vowel mark ー = 47 entries, frequencies 101–147, same KanjiVG pipeline) + 66 katakana loanwords, a persisted `activeScript` setting, and a Hiragana/Katakana selector in the Library that scopes what is studied, quizzed, and browsed. The learning engine and Room schema were **reused unchanged** (script filtering happens in the ViewModel before `LessonGenerator`; katakana rows are additive — no migration). A 2026-07-04 **dakuten/handakuten** addition then added the voiced (が/ざ/だ/ば) and semi-voiced (ぱ) kana for both scripts (25 each: hiragana freq 47–71, katakana 148–172, same pipeline) plus their words, but as an **opt-in**: a persisted `includeDiacritics` setting (default OFF) gates them out of session generation, the quiz, word-unlock, and the Library lists so beginners meet only the base gojūon; a "Voiced kana (゛゜)" toggle in the Library folds them into the active script (after the base kana, by frequency) when the learner is ready. Classification is derived from the glyph (`KanaKind`, via Unicode NFD); engine and Room again unchanged (dakuten rows additive; off-scope cards are inert orphans). A 2026-07-04 **yōon** addition then added the contracted syllables (きゃ/しゅ/きょ …, 33 per script: hiragana freq 72–104, katakana 173–205) plus their words — the app's first **composite characters** (a 2-code-point glyph like "きゃ" with NO single KanjiVG file, so geometry is composed from the base kana + a small ゃ/ゅ/ょ by `tools/import_kanjivg.py`). Yōon are a **second independent opt-in** (persisted `includeYoon`, default OFF; a "Combined kana (ゃゅょ)" Library toggle) gating them out of sessions/quiz/unlock/lists until the learner is ready. A centralized `KanaUnits` splitter groups a base + small ゃゅょ into one reading unit so yōon vocabulary unlocks correctly; engine and Room again unchanged (yōon rows additive, off-scope orphans inert). Device-verified on the Pixel 7. A 2026-07-04 **extended-kana** addition then **completed the kana inventory**: the small tsu (っ/ッ), small vowels (ぁぃぅぇぉ/ァィゥェォ), ゔ/ヴ, 22 extended-katakana foreign-sound composites (ファ/ティ/ウェ/ヴァ/シェ/チェ/ツォ …), and the obsolete ゐゑ/ヰヱ — behind a **third opt-in** (`includeExtended`, default OFF; "Extended kana (っ ァ)" Library toggle). `KanaUnits` now fuses small vowels too (so ソファ→ソ, ファ unlocks); the extended composites reuse the yōon composition; ゔ/ヴ classify as dakuten (they sit under the Voiced opt-in, not Extended). The app now covers **all hiragana and katakana** (base, dakuten/handakuten, yōon, extended): 113 hiragana + 136 katakana characters, ~397 words. Device-verified. Phase 1 `assembleDebug` on 2026-07-03; Phase 2 implemented and built 2026-07-03, re-verified/reviewed/fixed 2026-07-04; Phase 3 implemented, built, and unit-tested 2026-07-04 (`assembleDebug` + `testDebugUnitTest` both green, 45 unit tests / 0 failures — the project's first tests) and adversarially reviewed (2 agents, 0 P0, both verdicts ship; review fixes applied per `docs/PHASE3-DESIGN.md` §11). **All of the above has since been device-verified on a Pixel 7 (Android 16)**, including the live Room migrations. Further additions, also device-verified: a handwriting-quality **scorer** (`domain/scoring/` — pure geometry form/fit dials + ML Kit digital-ink recognition; advisory only, never touches SRS) persisted via **Room v3** (`MIGRATION_2_3` adds nullable `form_score`/`fit_score`/`recognition_score` columns to `practice_history`); a write-from-memory **"Quiz me!"** overlay (`QuizScreen`, `PracticeSource.QUIZ`, no SRS side effects); a Library **list⇄chart** view (a gojūon cheat-sheet built by `domain/model/KanaChart.kt`); a persisted **brush ink color**; and a **rebrand to "HiraKataQuest"** with a new hinomaru launcher icon (vermilion circle + white print あ/ア, adaptive vector from `ic_launcher_foreground.xml`/`ic_launcher_monochrome.xml`). A 2026-07-05 batch then **removed the guided SRS study session entirely** (the SM-2 `SrsScheduler`, the `LessonGenerator`, the `StudySession` model, the `PracticeActionBar` grade bar, the COMPLETE summary, and the whole `REVIEWS`/`NEW_CHARACTER`/`PRACTICE`/`VOCABULARY`/`COMPLETE` state machine — `SessionPhase` is now just `LOADING`/`FREE`): the app is now **free practice + the "Quiz me!" quiz** only. Structured learning is instead provided by **~32 seeded, editable default practice sets** (`domain/model/DefaultPracticeSets.kt`) — for BOTH scripts: the 10 gojūon rows + three deck-derived categories (Voiced/Combined/Extended) + a few starter word sets (colors/nature/seasons; food/countries/everyday items) — seeded once per install via a persisted `default_sets_seeded` flag (`SettingsRepository.hasSeededDefaultSets()`/`setDefaultSetsSeeded()`, done in `PracticeViewModel.seedDefaultSetsIfNeeded()` on `startPractice()`); afterwards they are ordinary editable sets (rename/delete/edit; a deleted default does not reappear). **Room is untouched at v4** — the `review_cards`/`character_progress`/`vocabulary_progress` tables + their entities/DAOs + `RoomLearningRepository`/`RoomVocabularyRepository` **remain as dormant schema** (removing them would be a non-additive migration); `AppContainer.learningRepository` is still constructed but no longer injected into the ViewModel. Build + **84 tests** green; device-verified on the Pixel 7 (Android 16) via an in-place upgrade. This supersedes the session-based flow described above; all prior "session generation / review / new-character / vocabulary / COMPLETE summary" mentions are historical. A 2026-07-09 batch (branch `feat/reading-writing-split`, 11 commits) then **split the app into two top-level tracks behind a new opening screen** (`OpeningScreen`, two cards Reading/Writing): a persisted `AppMode` (READING/WRITING, key `app_mode`) drives which track the user is in. **Launch no longer auto-enters free practice** — a cold start with no saved mode shows the opening screen (`PracticeUiState.appMode == null`); only WRITING enters free practice (after the pick). The **WRITING** track is the pre-existing handwriting app (free practice + write-from-memory quiz), now always using the HANDWRITTEN (KanjiVG-stroke) ghost — the old Printed/Handwritten "Character style" selector was replaced by an "I want to practice" Reading|Writing toggle, so the standalone print/handwritten choice is gone (`CharacterForm` survives only as `TracingCanvas`'s render param, forced HANDWRITTEN). The **READING** track inverts everything: a **flashcard study mode** (`ReadingFlashcardScreen` — printed front → reveal reading + read-aloud + meaning → self-graded Got it/Missed, or an optional "Type the reading" romaji field checked with lenient `RomajiMatch`; self-grades are NOT recorded) plus a **reading quiz** (`QuizKind.READING`: shows the printed gothic glyph/word, learner answers by multiple-choice or typed romaji — `ReadingAnswerStyle.CHOICE/TYPE` — with an optional "Also test meaning" for words; pass/fail, no writing score). Reading progress is tracked in a NEW **Room v5** `reading_progress` table (`MIGRATION_4_5`, `app/schemas/5.json`) with two independent per-glyph/word tallies (multiple-choice + typed-romaji attempts/correct); `ReadingProgress.mcqPercent`/`typePercent`/`colorPercent` back a reading-mode Library color-coding + sort (MC/Type/Avg), separate from the writing score. The "Score my writing" picker is hidden in Reading mode. Build + **~95 tests** green (adds `RomajiMatchTest`); device-verified on a Pixel 7 (Android 16) incl. the live v4→v5 migration. A 2026-07-25 **mnemonics** batch (branch `feat/mnemonics`) then added keyword+story memory aids for the 46 base hiragana: `domain/model/KanaMnemonics.kt` ships an owner-picked default plus alternates per kana (164 entries; candidates were authored by a 29-agent workflow, curated, and picked by the owner from a review artifact — his own suggestion lists were merged in as candidates too), 10 defaults carry hand-authored vector overlay accents drawn over the real strokes (validated + contact-sheeted by `tools/render_mnemonic_overlays.py`), and the UI is a "How to remember" chip (practice footer, flashcard + reading-quiz reveals, post-submit writing quiz) + pre-answer "Hint" buttons (text-only in the writing quiz) opening a dialog that shows one mnemonic plus a "Show more" button revealing the alternates — each learner can promote whichever alternate clicks for them (persisted per kana, `mnemonic_choices`), because everyone's brain hooks onto different images (user decision). The vector overlay accents were **disabled** on 2026-07-26 (they did not read at dialog size; the data model + blocks are retained for an externally-authored redraw). All of it sits behind a persisted "Memory hints" toggle (`mnemonics_enabled`, default ON) and never touches scoring. An adversarial review (38-agent workflow: 8 finder angles + per-finding verify) then hardened it: stories may never contain kana glyphs (they leaked the writing-quiz answer through the hint dialog — twins are named by romaji now, test-pinned), を's copy teaches "sounds like o, typed wo" AND `RomajiMatch` accepts typed "o" for expected "wo" (one-directional), the flashcard 0.5/0.5 weight bump reverted to divergence-only (it had shrunk the glyph across the whole base deck), and the writing quiz's post-submit chip moved INTO the answer row (the 0.22 header column clipped on short screens). Build + **158 tests** green; **device verification pending**. A 2026-07-27 batch (same `feat/mnemonics` branch) then promoted **Practice sets to a first-class Library tab** (`SetsTabContent`): a third tab beside Characters and Words (labels keep live counts + share one `rememberUniformTextScale` so they fit at 360dp), scoped to the active script, driven by the shared top-bar search, with a "New" chooser (Character/Word set) — replacing the old Study-scope-sheet "Add practice set" / "See sets" buttons; the persisted `library_section` pref gains index 2 (falls back to a character on resume). Build + **163 tests** green; device verification pending. A 2026-07-27 **dark mode** batch (branch `feat/dark-mode`) then added an **app-controlled light/dark theme**: a persisted three-way Appearance setting (System / Light / Dark, enum `AppearanceMode`, key `appearance`, default LIGHT so existing installs are pixel-identical until opt-in) at the bottom of the Study-scope sheet. `Theme.kt` gained a warm "sumi / night-washi" `darkColorScheme` (`HiraganaTheme(darkTheme)`); a new `KanaColors`/`LocalKanaColors` canvas palette carries the six formerly-hardcoded "paper" colors (sheet, ghost, grid×2, diagram grey, default ink) so **the writing worksheet itself darkens** (dark sheet + hairline edge, dimmed ghost/grid, and a **light "chalk" default ink** via a second per-theme pref `brush_ink_color_dark` — the same Options ink row edits whichever appearance is active); `scoreSpectrumColor(score, dark)` and `ScoreFeedbackCard.qualityBand(score, dark)` gained low-luminance dark twins so their light on-color text stays legible on the tints. `MainActivity` hoists the ViewModel, resolves `AppearanceMode.resolvesToDark()` (SYSTEM → `isSystemInDarkTheme()`), wraps `HiraganaTheme(darkTheme)`, and re-applies `enableEdgeToEdge(SystemBarStyle…)` on the resolved darkness (fixing a latent light-icons-on-system-dark bug) plus pre-darkens the window background in `onCreate` to kill the cold-start flash. `forceDarkAllowed` stays false — dark is designed, not platform-inverted. Build + **171 tests** green (adds `AppearanceModeTest` + 4 VM cases); **device verification pending**. A follow-up added a writing-quiz summary **sort-by-score** toggle + a **"retake the ones that need work"** score-cutoff button (`retryBelowScore`, default 80; the writing twin of reading's retry-missed) — build + **173 tests** green. ## Conventions & architecture rules

- **Manual DI only.** Dependencies live in `AppContainer` (`HiraganaApplication.kt`): lazy Room DB + `AssetCharacterRepository` + `RoomPracticeRepository` + (Phase 3) `RoomLearningRepository` + `RoomVocabularyRepository`, sharing one lazy `HiraganaAssetDataSource`. ViewModels get them via `PracticeViewModel.Factory`. Do not introduce Hilt/Koin.
- **State split.** `PracticeViewModel` owns deck/free-practice state only (`PracticeUiState` via `StateFlow`; `SessionPhase` is now just `LOADING`/`FREE`). ALL transient drawing state lives in `CanvasState`, a `@Stable` snapshot-state holder cleared by a `LaunchedEffect` keyed on `PracticeUiState.canvasClearKey` — keep drawing state OUT of `PracticeViewModel`. Since 2026-10-16 it lives in a private activity-scoped `CanvasStateHolder` ViewModel in `PracticeScreen.kt` (not a plain `remember`), so ink survives Activity recreation (font size, system dark mode, display size, locale); the holder records the clear key it last cleared for, so the re-run effect doesn't wipe kept ink. Ink is stored in canvas px, so `TracingCanvas` calls `CanvasState.fitToSheet(cells)` every draw pass: if the same sheet's cells moved, each stroke maps from its old cell to the same-index new cell (`drawing/canvas/SheetRemap.kt`, `SheetRemapTest`) and its ribbon is rebuilt at the new brush width; a different cell count drops the ink. Process death still loses ink along with the current character. Submitting a free-practice attempt snapshots the session synchronously and fire-and-forgets the (optional, scoring-gated) Room insert.
- **Input path.** `TracingCanvas` uses `pointerInteropFilter` -> `StrokeCapture`: raw MotionEvents, batched historical samples, pressure coerced 0..2, single-active-pointer palm rejection, stylus + finger. Don't replace with `detectDragGestures` — pressure and history would be lost.
- **Render order** (TracingCanvas): 2x2 dashed grid -> font-rendered light-grey ghost glyph (native `canvas.drawText`) -> completed strokes -> active stroke. Ink is a **filled variable-width brush ribbon** (`StrokeRenderer.buildBrushPath`): 20dp base width x cell-proportional scale (`brushScale(cellSide, referenceSide)` in TracingCanvas.kt — reference is the single-character 2×2 cell; smaller cells, incl. word rows and dense layouts, thin the ink linearly, growth above the reference is half-slope so the 1×1 sheet lands at ~1.5×; safe because every cell-size change bumps `canvasClearKey`) x per-point pressure scale (0.55..1.6, same curve as Phase 1) x per-point speed thinning (fast flicks thin to 0.55), moving-average width smoothing, head taper always, tail taper only on commit (the live stroke keeps a full-width tip), round end caps as discs; centerline and both edges midpoint-quadratic smoothed. Width is baked into the path in px (`CanvasState.brushBaseWidthPx`, refreshed each draw pass), so consumers just fill — no Stroke style, no width multiplier.
- **Brush ink color is a purely-visual persisted setting.** The user picks the ink color (default charcoal `InkBlack`) via the `BrushColorPicker` HSV dialog, opened from a labeled **"Brush ink color" row at the bottom of the "Study scope"/Options `ModalBottomSheet`** (a `LibraryScreen` param wired from `PracticeScreen` → `ScopeSheetContent`, NOT on the practice canvas chrome). It moved there from the app-bar swatch on 2026-07-08 so it reads as the labeled setting it is; the app-bar slot it vacated now holds the list Sort menu. Stored as a raw ARGB `Int` (`SettingsRepository.get/setBrushInkColor`, key `brush_ink_color`, default `0xFF20222E` = `InkBlack`) — any color is valid, so no enum/decoder. It rides `PracticeUiState.brushInkColor` (seeded at construction, preserved across every state reconstruction — same discipline as `activeScript`/`isLibraryGridView`) into `TracingCanvas`'s `inkColor` param, which colors user ink **at draw time** (`drawPath(path, color = inkColor)`) for BOTH practice and the quiz (same `TracingCanvas`). Reactive param, NOT a `CanvasState` field, so a setting change actually recomposes/redraws. It touches ONLY rendering — never stroke geometry, scoring, or scheduling; the didactic grey ghost glyph and stroke-order preview are unaffected. Committed on the picker's "Done" (Cancel/dismiss discards). Since 2026-07-27 dark mode keeps a SECOND ink (`brush_ink_color_dark`, default chalk `InkChalk` 0xFFEFE7DA, `PracticeUiState.brushInkColorDark`/`setBrushInkColorDark`); the same Options row edits whichever appearance is active, and `PracticeScreen` resolves the active ink off `LocalKanaColors.current.isDark` for both the practice and quiz canvases.
- **Brush effect is a second purely-visual persisted setting (2026-07-23), a sibling of the ink color.** A `drawing/canvas/BrushEffect` enum (BRUSH / CALLIGRAPHY 筆 / FOUNTAIN_PEN / MARKER; default **BRUSH** reproduces the original ribbon so existing installs are unchanged) lets the learner pick the artistic stroke style. It's a **vector-only** set: each effect carries a `BrushSpec` (a `WidthProfile` = Uniform / Tapered / Dynamic, a `widthScale`, a fill `alpha`, and a `Cap` = Round / Square / Pointed), so every effect is still a **single filled Path** — no textures, no multi-primitive rendering, no richer per-stroke storage. `StrokeRenderer.buildBrushPath(points, baseWidthPx, profile, cap)` now computes a per-point half-width array (Uniform = constant; Tapered = end-ramped; Dynamic = calligraphy: speed [dist/dt from timestamps] × pressure, binomial-smoothed, tapered to a point) and shapes the end caps (Round keeps the cap discs; Square projects the rim along the tangent; Pointed closes to a point). Geometry is **baked at input time**, so `CanvasState.brushEffect` is published by `TracingCanvas` each draw pass exactly like `brushBaseWidthPx`, and `buildActivePath`/`commitStroke` pass `brushBaseWidthPx * spec.widthScale` + the profile/cap; the fill `alpha` (e.g. the translucent marker) is applied at draw time. Because switching effect changes committed geometry, `setBrushEffect` **bumps `canvasClearKey`** (clears the sheet + pending feedback, same rule as `setPracticeLayout` — unlike the color setter, which doesn't). Threaded end-to-end like `brushInkColor`: `SettingsRepository.get/setBrushEffect` (key `brush_effect`, stored as `prefValue`, `fromPrefValue` fallback → BRUSH), `PracticeUiState.brushEffect` (seeded + preserved in `rebuilt()`), `PracticeScreen` → `TracingCanvas` (practice + quiz) + `LibraryScreen`/`ScopeSheetContent`'s "Brush effect" row (beside "Brush ink color") which opens `presentation/components/BrushEffectPicker` — a preview dialog that renders each effect's sample stroke via the real `StrokeRenderer`. **Never affects scoring** (the scorer reads raw `StrokePoint`s from `DrawingSession`, not the rendered Path). Tests: `BrushEffectTest` + two `PracticeViewModelTest` cases (persist-and-clear, survives-scope-rebuild).
- **Audio pronunciation via the device TTS (2026-07-06).** A small speaker button sits next to the romaji everywhere a reading appears (guide panel char + word, Library list rows + word-grid cards, quiz running prompt + summary; the dense gojūon **chart cell is intentionally omitted** — no room). One `domain/audio/PronunciationPlayer` interface (`status`/`play(glyph)`/`refresh()`/`release()`) with a single impl `data/audio/TtsPronunciationPlayer` (framework `TextToSpeech`, ja-JP, fed the raw kana GLYPH not romaji — a single character and a whole word are both glyph strings, so one code path). `status` is a `VoiceStatus` (READY / NEEDS_DOWNLOAD / UNAVAILABLE), flipped once the async init reports a voice: **READY** → tap speaks; **NEEDS_DOWNLOAD** → tap opens the system `ACTION_INSTALL_TTS_DATA` installer (fallback: `com.android.settings.TTS_SETTINGS`) so the user can download the Japanese voice; **UNAVAILABLE** → button greys out. `TextToSpeech` is a **framework API — NO app dependency, no permission, no manifest/Room change**. Wired like `handwritingRecognizer`: a lazy `AppContainer` val → `PracticeViewModel.Factory` → `speakTts(glyph)` + `refreshTtsAvailability()` + `ttsStatus` UI state. It is an **Application-scoped singleton and is deliberately NOT released in `onCleared()`** — doing so would shut down the shared engine when the Activity finishes (e.g. Back out of the app) while the process lives on, leaving the next launch with a dead engine and silent audio; the OS reclaims it on process death (same as `handwritingRecognizer`). `PracticeScreen` re-checks on `LifecycleEventEffect(ON_RESUME)` so a freshly-installed voice flips NEEDS_DOWNLOAD→READY without a restart. Shared UI: `presentation/components/PronunciationButtons.kt` (the `PronunciationButton` composable owns the install-intent launch via `LocalContext`). (History: this began 2026-07-06 as a two-engine A/B demo with bundled `assets/audio` MP3 clips + `tools/generate_audio.py`; the clip engine was dropped the same day in favor of TTS-only + the voice-download flow.) **Auto-narration (2026-07-23, opt-in, Writing only):** a persisted `SettingsRepository.isAutoNarrateEnabled` (key `auto_narrate_enabled`, default false) + a "Read aloud automatically" Switch in the Study-scope sheet's Writing-only block (below "Score my writing"). When on, a new character/word is spoken the instant it appears — in free practice AND the writing quiz. It's driven from the UI (`PracticeScreen` computes a `narrateGlyph` off `PracticeUiState` — the free `freeWord.kana`/`currentCharacter.character`, or the writing quiz's `current.answer` while RUNNING — and a `LaunchedEffect(narrateGlyph)` calls `speakTts`, remembering the last-spoken glyph so returning from the Library to the same glyph doesn't repeat), NOT from the ViewModel, so it covers every transition (Next, Library pick, scope change, each quiz item) with one rule. Gated on `ttsStatus == READY`; `PracticeUiState.readingAutoSpeakEnabled` seeded + `rebuilt()`-preserved; `setReadingAutoSpeak` persists + publishes.

- **Handwriting scoring is a MEASUREMENT, never a cap (2026-08-02 rework).** Two device reports ("simple katakana always score 65", "a random line scores 45") had one root cause: `CharacterScore.combine` ended in `headline.coerceAtMost(65 or 45)`, and because a clamp is a *maximum*, those two constants became the modal output — the number shown was a constant, not a measurement. The rework, in four parts: (1) **recognition is a multiplier, not a clamp** (`legibilityFactor`: recognized 1.00 / rank 1 0.92 / rank 2 0.86 / rank 3+ 0.80 / absent 0.70) so it can never invent a floor, and the discount is gentle *by design* because geometry compares against the character's ACTUAL reference strokes while ML Kit is general-purpose with systematic blind spots on this deck (homographs, yōon composites, extended katakana, obsolete ゐ/ヱ) — a harsh factor would quietly punish whole classes of character forever while buying nothing at the bottom, where geometry already lands near zero. (2) **`GeometryScorer` gained a symmetric chamfer `resemblance()` gate** over every point on both drawings (`coverage` = did you draw the whole character, `precision` = did you draw anything that ISN'T the character, combined as a geometric mean, applied multiplicatively). This is what finally makes **surplus strokes cost**: the per-stroke pass only ever inspects the first `min(user, reference)` strokes in draw order, so scribbling 10 strokes on a 3-stroke glyph left 7 uninspected. (3) **No mode is shape-blind any more** — `FIT` measures only the ink's bounding box (a single centred line scores ~94 on it), so `BOTH` stopped being the AVERAGE of the dials (`form * (0.65 + 0.35 * fit/100)`, form-dominant) and `FIT`-only is gated by form. (4) `directionSimilarity` returns `max(0, cos)` instead of remapping [-1,1]→[0,1], which had handed randomly-angled ink half the dial for free. Also fixed a genuine measurement bug: the shape term now scores on the BETTER of forward/reverse alignment, so a backwards stroke is charged ONCE (by the direction dial + an explicit `BACKWARDS_PENALTY`) instead of twice, with the double-charge hidden inside an index-alignment artifact. **Calibration is pinned by `GeometryScorerCalibrationTest`**, which asserts BANDS for what a learner actually experiences (exact trace ≥95, wobbly 82+, single random line ≤12, scribble ≤15, wrong stroke order 35–70, missing stroke 30–65, all-backwards 40–75, neat nonsense ≤25 in EVERY mode) plus two properties: degrading input must MOVE the score (no value may dominate a sweep) and recognition may never RAISE one. The constants (`COVERAGE_TOLERANCE`, `GATE_FULL`, `BACKWARDS_PENALTY`, the legibility factors) are tunable **only against those bands** — that suite exists because hand-tuned constants left the scores impossible to argue with. Device-verified: エ 93 (was 65, no "Looks more like 工"), random line 7 (was 45), box-filling diagonal in FIT mode 15 (was ~94).
