# CLAUDE.md — HiraKataQuest

**HiraKataQuest** — an Android app for practicing Japanese **kana** (hiragana + katakana, all groups). Since 2026-07-09 it splits into two top-level tracks behind an opening screen (`AppMode` READING/WRITING): **Writing** = trace a light-grey ghost glyph on a genkouyoushi-style grid with stylus or finger (free practice + a write-from-memory "Quiz me!" mode), attempts persist to Room; **Reading** = printed-glyph flashcards + an inverted reading quiz (recognize the glyph, answer by choice or typed romaji). Structured learning comes from **built-in default practice sets** (a guided SRS study session existed through 2026-07-04 but was removed 2026-07-05 — see the Status paragraph). Handwriting is auto-scored when the Score-my-writing setting is on. Kotlin, Jetpack Compose, Material 3, MVVM, Room via KSP, manual DI (no Hilt). Single module `:app`, single screen, package `com.hive.hiragana` (the package/`applicationId` is unchanged by the rename — the user-facing name lives in `strings.xml`).

**Status: Phase 1 (static tracing MVP), Phase 2 (animated stroke-order demonstrations), and Phase 3 (Smart Learning System — SRS scheduling, personalized sessions, vocabulary unlocking) are all COMPLETE**, plus a 2026-07-04 post-device-feedback batch: KanjiVG-sourced stroke geometry (viewBox 109, CC BY-SA attribution required — see `tools/import_kanjivg.py`), brush-ribbon ink rendering, a Start-next-session button on the COMPLETE summary, a Library overlay for free practice of any character/word, and a force-dark opt-out. Two 2026-07-04 content expansions then grew the deck from 5 to the full 46-character basic gojūon (あ〜ん via the same KanjiVG pipeline, frequencies = gojūon order 1–46; no dakuten/yōon yet) and `vocabulary.json` to 153 common words (every kana except を covered). A 2026-07-04 **katakana section** then added a second script alongside hiragana (device-verified on the Pixel 7): a `Script` enum + `assets/katakana/` (46 homologues + the long-vowel mark ー = 47 entries, frequencies 101–147, same KanjiVG pipeline) + 66 katakana loanwords, a persisted `activeScript` setting, and a Hiragana/Katakana selector in the Library that scopes what is studied, quizzed, and browsed. The learning engine and Room schema were **reused unchanged** (script filtering happens in the ViewModel before `LessonGenerator`; katakana rows are additive — no migration). A 2026-07-04 **dakuten/handakuten** addition then added the voiced (が/ざ/だ/ば) and semi-voiced (ぱ) kana for both scripts (25 each: hiragana freq 47–71, katakana 148–172, same pipeline) plus their words, but as an **opt-in**: a persisted `includeDiacritics` setting (default OFF) gates them out of session generation, the quiz, word-unlock, and the Library lists so beginners meet only the base gojūon; a "Voiced kana (゛゜)" toggle in the Library folds them into the active script (after the base kana, by frequency) when the learner is ready. Classification is derived from the glyph (`KanaKind`, via Unicode NFD); engine and Room again unchanged (dakuten rows additive; off-scope cards are inert orphans). A 2026-07-04 **yōon** addition then added the contracted syllables (きゃ/しゅ/きょ …, 33 per script: hiragana freq 72–104, katakana 173–205) plus their words — the app's first **composite characters** (a 2-code-point glyph like "きゃ" with NO single KanjiVG file, so geometry is composed from the base kana + a small ゃ/ゅ/ょ by `tools/import_kanjivg.py`). Yōon are a **second independent opt-in** (persisted `includeYoon`, default OFF; a "Combined kana (ゃゅょ)" Library toggle) gating them out of sessions/quiz/unlock/lists until the learner is ready. A centralized `KanaUnits` splitter groups a base + small ゃゅょ into one reading unit so yōon vocabulary unlocks correctly; engine and Room again unchanged (yōon rows additive, off-scope orphans inert). Device-verified on the Pixel 7. The app now covers **all hiragana and katakana** (base, dakuten/handakuten, yōon, extended): 113 hiragana + 136 katakana characters, ~397 words. Device-verified. Build + **84 tests** green; device-verified on the Pixel 7 (Android 16) via an in-place upgrade. A 2026-07-09 batch (branch `feat/reading-writing-split`, 11 commits) then **split the app into two top-level tracks behind a new opening screen** (`OpeningScreen`, two cards Reading/Writing): a persisted `AppMode` (READING/WRITING, key `app_mode`) drives which track the user is in. **Launch no longer auto-enters free practice** — a cold start with no saved mode shows the opening screen (`PracticeUiState.appMode == null`); only WRITING enters free practice (after the pick). ## Conventions & architecture rules

- **Manual DI only.** Dependencies live in `AppContainer` (`HiraganaApplication.kt`): lazy Room DB + `AssetCharacterRepository` + `RoomPracticeRepository` + (Phase 3) `RoomLearningRepository` + `RoomVocabularyRepository`, sharing one lazy `HiraganaAssetDataSource`. ViewModels get them via `PracticeViewModel.Factory`. Do not introduce Hilt/Koin.
- **State split.** `PracticeViewModel` owns deck/free-practice state only (`PracticeUiState` via `StateFlow`; `SessionPhase` is now just `LOADING`/`FREE`). ALL transient drawing state lives in `CanvasState`, a `@Stable` snapshot-state holder `remember`ed in `PracticeScreen` and cleared by a `LaunchedEffect` keyed on `PracticeUiState.canvasClearKey` — keep drawing state OUT of the ViewModel. Submitting a free-practice attempt snapshots the session synchronously and fire-and-forgets the (optional, scoring-gated) Room insert.
- **Input path.** `TracingCanvas` uses `pointerInteropFilter` -> `StrokeCapture`: raw MotionEvents, batched historical samples, pressure coerced 0..2, single-active-pointer palm rejection, stylus + finger. Don't replace with `detectDragGestures` — pressure and history would be lost.
- **Render order** (TracingCanvas): 2x2 dashed grid -> font-rendered light-grey ghost glyph (native `canvas.drawText`) -> completed strokes -> active stroke. Ink is a **filled variable-width brush ribbon** (`StrokeRenderer.buildBrushPath`): 20dp base width x cell-proportional scale (`brushScale(cellSide, referenceSide)` in TracingCanvas.kt — reference is the single-character 2×2 cell; smaller cells, incl. word rows and dense layouts, thin the ink linearly, growth above the reference is half-slope so the 1×1 sheet lands at ~1.5×; safe because every cell-size change bumps `canvasClearKey`) x per-point pressure scale (0.55..1.6, same curve as Phase 1) x per-point speed thinning (fast flicks thin to 0.55), moving-average width smoothing, head taper always, tail taper only on commit (the live stroke keeps a full-width tip), round end caps as discs; centerline and both edges midpoint-quadratic smoothed. Width is baked into the path in px (`CanvasState.brushBaseWidthPx`, refreshed each draw pass), so consumers just fill — no Stroke style, no width multiplier.
- **Brush ink color is a purely-visual persisted setting.** The user picks the ink color (default charcoal `InkBlack`) via the `BrushColorPicker` HSV dialog, opened from a labeled **"Brush ink color" row at the bottom of the "Study scope"/Options `ModalBottomSheet`** (a `LibraryScreen` param wired from `PracticeScreen` → `ScopeSheetContent`, NOT on the practice canvas chrome). It moved there from the app-bar swatch on 2026-07-08 so it reads as the labeled setting it is; the app-bar slot it vacated now holds the list Sort menu. - **Voiced kana (dakuten/handakuten) are opt-in.** `KanaKind` classifies every glyph BASE vs DAKUTEN vs HANDAKUTEN via Unicode NFD (voiced kana decompose to base + U+3099/U+309A), so nothing is stored in JSON. A persisted `SettingsRepository.includeDiacritics` (default **false**) is threaded into `ScriptScope.scopedCharacters/scopedWords`, which drop voiced kana (and words that use them, via `VocabularyWord.usesDiacritics`) unless it's on — gating the quiz, free practice, AND the Library lists in one place. Voiced-kana frequencies sit above the base band per script (hiragana 47–71, katakana 148–172).
- **Yōon are a second, independent opt-in — and the only composite characters.** A yōon (きゃ, しゅ …) has a 2-code-point glyph with NO single Unicode point, so: (a) its `strokes[]` are **composed** offline by `import_kanjivg.py` (base -i kana scaled left + small ゃ/ゅ/ょ scaled bottom-right — see `YOON`/`compose_yoon`), the app's only multi-source geometry; (b) `KanaUnits.split` groups a base + small ゃゅょ into ONE reading unit — the single rule shared by `VocabularyWord.fromKana` (so "きょう"→`{きょ, う}` matches the "きょ" deck char), `PracticeUiState.canvasGlyphs` (one cell per unit), `pronunciationOf`, and the stored word romaji; (c) `HiraganaCharacter.isYoon`/`VocabularyWord.usesYoon` gate them via persisted `includeYoon` (default **false**, the "Combined kana" `FilterChip`, `setIncludeYoon`), **independent** of the voiced opt-in — `ScriptScope` checks yōon first, so a voiced-base yōon like ぎゃ is gated by `includeYoon` alone. `drawGhostCharacter` shrinks-to-fit so the wider 2-glyph ghost never clips. Yōon frequencies sit above both prior bands (hiragana 72–104, katakana 173–205). Same additive/no-migration/inert-orphan story.
- **Extended kana are a third opt-in — completing the inventory.** `includeExtended` (default **false**, "Extended kana (っ ァ)" `FilterChip`, `setIncludeExtended`) gates the small tsu (っ/ッ), small vowels (ぁぃぅぇぉ/ァィゥェォ), 22 extended-katakana composites (ファ, ティ, ウェ, ヴァ, シェ, チェ, ツォ …), and obsolete ゐゑ/ヰヱ. `KanaUnits` now fuses small vowels as well as small ゃゅょ (so ソファ→`{ソ, ファ}` unlocks against the "ファ" deck char), but the small tsu stays its own unit (きって→`{き, っ, て}`); `isExtended`/`usesExtended` = has small vowel OR sokuon OR obsolete. `ScriptScope` is now a 4-flag gate with priority **extended → yōon → voiced**, so each opt-in stays independent — e.g. a foreign combo like ヴァ (voiced base + small vowel) is gated by `includeExtended` alone. Extended composites reuse `compose_composite` (the merged `COMPOSITES = YOON + EXTENDED` table); **`ゔ`/`ヴ` are NOT extended** — they decompose to a dakuten (`KanaKind`) so they live under the Voiced opt-in. Extended frequencies sit above yōon (hiragana 105–113, katakana 206–236). With all three opt-ins the deck is the complete kana set.

Loading/error branches have no handler (Back exits).
- No dark theme: hardcoded light status/navigation bar colors (`#FBF8F4`) in `themes.xml`; `HiraganaTheme` is light-only, and `android:forceDarkAllowed=false` opts out of system force-dark (without it, Pixel/Android 16 inverts the whole UI when the system is in dark mode — found in the first device run).
- Room `exportSchema = true` as of Phase 3, with the schema history committed at `app/schemas/`.
- The project is a **git repository published at `github.com/MolnarMario/HiraKataQuest`** (public). `.gitignore` excludes build outputs, `local.properties`, `.idea/`, and `.aihive/` (coordination metadata is not part of the app).
